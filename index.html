About

I build backend systems for data that does not fit in memory, and for models that should not be trusted blindly.

Right now that means EEG infrastructure at Avinya Neurotech: five FastAPI services covering ingestion, analysis, export, and live review of clinical recordings large enough that memory discipline stops being optional. Most of the interesting work there is not the feature list - it is deciding what runs inside the request path and what does not.

Almost everything I build follows one rule: models propose, deterministic code decides.

In Tempo, a local model drafts task structure but a typed Python service owns every date and every schedule. In Premiere Assist, FFmpeg evidence feeds a resolver that writes the edit list; the model never runs a command. In my retrieval work, search is hybrid and inspectable rather than a vector-store black box. Each time I give up flexibility, and each time I get back behaviour I can reproduce and explain - which matters more when the output is a medical trace or an insurance premium than when it is a demo.

The same instinct shows up as measurement. My final-year project set out to predict insurance premiums and turned into a leakage audit once the offline accuracy looked too good to be honest. The EEG benchmark exists because windowed signal processing fails quietly, so I timed it instead of assuming it was fine. When I do not have evidence for a claim, I would rather say so on the card than round it up.

I write the unpolished version of all this at Engineering Tales - broken assumptions, design choices, implementation details, and next steps.

Cloud EEG Ingestion & Analysis Platform

  • Problem: Medical EEG workflows needed reliable ingestion, analysis, exports, and real-time review for large datasets without exhausting memory.
  • Architecture: 5-service microservices platform with 50+ APIs, PostgreSQL for structured state, Redis for coordination/caching, Azure Blob Storage for large files, async jobs for analysis/export, and a streaming path for live review.
  • Tradeoffs: Moved heavy analysis out of request paths, favored object storage over local disk, and balanced real-time latency against batch frequency-band analysis and EDF+/PDF export jobs.
  • Outcome: Added bounded time-window streaming with stale-request cancellation; profiling reduced first-chunk latency to 783ms p50 and server send time to about 12ms.

MediPredict Insurance Premium ML Platform

  • Problem: Build a medical-insurance premium assistant that can serve quote-time predictions while explaining model behavior and avoiding misleading offline accuracy.
  • Architecture: React frontend and Spring Boot backend call an independently built FastAPI ML microservice with typed prediction schemas, artifact-driven model loading, health/readiness endpoints, Docker support, and a premium-prediction contract.
  • Tradeoffs: Separated quote-time prediction from renewal-time signals, rejected temporally leaked features such as realized annual medical cost for new applicants, and favored interpretable histogram gradient boosting over heavier or misleading alternatives.
  • Outcome: Produced an unpublished research study that exposed target leakage, separated quote-time from renewal-time signals, added SHAP/permutation explanation payloads, and documented fairness, reproducibility, and cross-dataset leakage checks.

Windowed EEG Benchmark

  • Problem: Identify silent correctness failures when standard EEG DSP is applied window by window rather than to a whole recording.
  • Architecture: Reproducible NumPy/SciPy/MNE experiments compare overlap-add, safe-window scheduling, edge policies, and bandpower equivalence.
  • Tradeoffs: Correctness and directly timed per-window latency take priority over broad framework throughput claims.
  • Evidence: Worst p95 filter-plus-feature latency was 6.46ms on 8-channel CHB-MIT and 1.63ms on 2-channel Sleep-EDF.

Local-First RAG Chatbot

  • Problem: Search private documents locally while keeping retrieval behavior inspectable across UI, CLI, and programmatic clients.
  • Architecture: FAISS dense search and BM25 sparse search are fused with RRF; SQLite retains metadata and MCP exposes structured access.
  • Tradeoffs: The local store favors inspectability and one-writer simplicity over distributed scale.
  • Evidence: On a fixed synthetic regression set, hybrid search retained Hit Rate@3 of 1.000 and improved MRR from 0.972 to 1.000; this is not a general quality benchmark.

Systems project NAND → assembler

Nand2Tetris Hardware Stack & Two-Pass Assembler

  • Problem: Build a small computer from first principles and translate Hack assembly into executable 16-bit machine code.
  • Architecture: HDL logic gates, ALU, memory hierarchy, program counter, memory-mapped I/O, plus a Python assembler split into parser, code-generation, symbol-table, and orchestration modules.
  • Tradeoffs: Used explicit translation tables and a two-pass algorithm for correctness and readability; chose Python over tutorial C++ to avoid copying and make the implementation easier to inspect.
  • Outcome: Built through the hardware portion, reached 16K memory, implemented an ALU capable of 18 operations via 6 control bits, and generated .hack binary output from .asm programs.
