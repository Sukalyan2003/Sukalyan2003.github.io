The brief

I build backend systems for data that does not fit in memory, and for models that should not be trusted blindly.

I did not set out to work on brains. I set out to work as a backend engineer, and the role that found me happened to involve EEG. What kept me there was the constraint. Clinical recordings are large enough that one careless query exhausts memory, windowed signal processing fails quietly rather than loudly, and the output is eventually read by someone making a decision about a patient. That domain does not tolerate the habits you can get away with elsewhere, and it rewrote how I build.

Models propose. Deterministic code decides.

In Tempo, a local model drafts task structure but a typed Python service owns every date and every schedule. In Premiere Assist, FFmpeg evidence feeds a resolver that writes the edit list; the model never runs a command. In my retrieval work, search is hybrid and inspectable rather than a vector-store black box. Every time, I trade flexibility for behaviour I can reproduce and explain - which matters more when the output is a medical trace or an insurance premium than when it is a demo.

The same instinct governs how I work with people. I would rather over-communicate and put a decision on the record than assume everyone is carrying the same context implicitly. The expensive failures I have watched were rarely technical; they were two people each confident they had already agreed.

It is also why the numbers on this page arrive with their limits attached. My final-year project set out to predict insurance premiums and turned into a leakage audit once the offline accuracy looked too good to be honest. The EEG benchmark exists because windowed processing fails silently, so I measured it rather than assuming it was fine.

The habit I am actively working against is overengineering - building for a scale and a set of cases a system may never meet. Naming the failure mode has not cured it, but it has made me slower to reach for the abstraction.

Away from a keyboard I read, more than I do anything else.

Cloud EEG Ingestion & Analysis Platform

ProblemMedical EEG workflows needed reliable ingestion, analysis, exports, and real-time review for large datasets without exhausting memory.
BuiltA five-service platform with 50+ APIs. PostgreSQL and TimescaleDB for structured state, Redis for coordination and job queues, Azure Blob Storage for large files, async jobs for analysis and export, and a bounded streaming path for live review.
TradeoffMoved heavy analysis out of the request path, chose object storage over local disk, and balanced real-time latency against batch frequency-band analysis and EDF+/PDF export jobs.
EvidenceAdded bounded time-window streaming with stale-request cancellation, plus a binary columnar wire format that cut payload from about 1.3 MB to 288 KB per chunk. Profiling took first-chunk latency from roughly 2.2 s to 783 ms p50 and server send time from about 250 ms to 12 ms, leaving the database fetch as 87% of what remains.

MediPredict ML Microservice

ProblemServe quote-time insurance premium predictions while explaining model behaviour and avoiding misleading offline accuracy.
BuiltI built the FastAPI ML microservice, and only that: typed prediction schemas, artifact-driven model loading, preprocessing shared with training, health and readiness endpoints, SHAP payloads and Docker packaging. A separate Spring Boot and React application, written by the rest of the project team, consumes it over HTTP. I did not write that backend or that frontend.
TradeoffSeparated quote-time prediction from renewal-time signals, rejected temporally leaked features such as realised annual medical cost for new applicants, and favoured interpretable histogram gradient boosting over heavier but misleading alternatives.
EvidenceA reported R² of 0.925 traced to a realised annual-cost field that does not exist when a quote is issued. A fixed-model feature ablation put the honest quote-time ceiling near R² 0.15, and a cross-dataset audit reproduced the collapse while leaving leakage-free datasets untouched. Swapping random forest for histogram gradient boosting cut the served artifact from 95.8 MB to 0.39 MB and single-row inference from roughly 45 ms to 0.5 ms at unchanged cross-validated accuracy. Written up as an unpublished manuscript.
